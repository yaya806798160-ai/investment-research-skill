# Investment OS → ChatGPT 实时桥接

目标：用户只需要在 ChatGPT 里问“现在呢/14:30怎么操作”，ChatGPT 直接读取 Investment OS 的最新盘中快照，不再依赖搜索引擎抓分钟级行情。

## 数据流

Investment OS / WorkBuddy / Codex 本地采集 → 统一 JSON 快照 → GitHub `bridge/live/latest.json` → ChatGPT 通过 GitHub 连接器读取 → 基金操作决策。

## 关键刷新时点（Asia/Shanghai）

交易日优先在 09:35、10:00、11:25、13:30、14:00、14:15、14:30、14:35、14:45、14:52 强制刷新；14:00–15:00 可每 5 分钟更新一次。每次都写 `generated_at` 与每个数据源自己的 `source_time`，防止旧数据冒充实时数据。

## 必须字段

- 指数：上证、创业板、科创50，涨跌幅、成交额/成交量、时间戳
- 市场宽度：上涨/下跌/涨停/跌停家数
- 板块/主题：CPO/光模块、PCB、AI算力、半导体设备、国产GPU/AI芯片
- 每个主题：涨跌幅、主力净流入、超大单净流入、成交额、涨停数、20CM涨停数、核心股
- 核心股：14:00后的分时方向、涨跌幅、成交额/量比、主力净流入、是否回流/破位
- 基金映射：财通成长C、东方人工智能、永赢数字经济智选C、华夏国证半导体008888对应主题强弱
- 数据质量：来源、时间、失败项、是否为实时/延迟

## 决策原则

1. 先读 `bridge/live/latest.json`，只有数据过旧或缺失才回退到网页搜索。
2. 14:30–14:55 优先判断真实资金与涨停扩散，不用新闻替代行情。
3. 采用“第一笔试错、第二笔确认、反弹兑现”。
4. 结论必须给：买/卖/不动 + 基金 + 金额/仓位 + 导致改变的客观数据。
5. 若 `generated_at` 距当前时间超过 8 分钟，标记为 stale，不允许当成实时证据。

## 验收案例

2026-09-14 14:30 后若 PCB 出现“双20CM涨停 + 多只10CM涨停 + 板块资金净流入”，即使通信/半导体大类仍净流出，也必须识别为“PCB局部主升/扩散”，并映射到财通成长C，作为第二笔进攻候选，而不是只看科技大类总资金流。
